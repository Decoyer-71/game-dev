**구현으로 바로 넘어가지 않는다** (2026-07-28 "바로 구현하지말고" 지적). 아이디어를 들으면 설계안을 먼저 정리해 검토받고, 승인 뒤에 코드를 쓴다.

**Why:** 게임 감각에 관한 결정(수치, 확률, 중첩 규칙, 어떤 요소에 무엇을 붙일지)은 내가 혼자 정할 것이 아니다. 상태이상 도입 때 내가 임의로 정하려던 항목이 대여섯 개였고, 그중 하나(마비의 강도)는 잘못 잡으면 밸런스를 통째로 무너뜨리는 것이었다.

**뼈대는 프로토타입 범위보다 깊고 넓게 잡는다** (2026-07-28 사용자 방침). 프로토타입은 전투 유형 몇 가지만 끝까지 만들지만, **구조는 최종 규모를 견디게** 설계한다. 예: 무공은 개별 데이터(이름·문파·수치)로, 문파별 특징을 먼저 확실히 정의한 뒤 밸런싱한다.
이게 가능한 이유는 [[jianghu-core-unity-split]] — 게임 규칙이 Unity 밖 순수 C# 이라 구조를 넓게 잡아도 검증 비용이 거의 안 든다.

**How to apply:** 새 시스템을 넣기 전에 ① 무엇을 정해야 하는지 목록화 ② 각각에 대한 제안과 근거 ③ 대안과 위험을 제시하고 합의한 뒤 구현한다. 콘텐츠(문파·무공명 등)는 지어내지 말고 [[concept-review-process]] 대로 자료조사를 거친다.
