사용자는 **Unity 경험이 전혀 없다**(2026-07-27 본인 고지). CK3 모드 작업 경험이 있어 스크립트·데이터 파일 다루기와 작업 규율에는 익숙하지만, Unity 에디터 UI·용어·워크플로는 모른다.

그리고 **응답이 비동기다.** 내 메시지에 바로 답하지 않고 시간이 지나서 돌아오기 때문에, **지난번에 무엇을 했는지 잊은 상태로 읽는다**(2026-07-28 본인 고지).

**How to apply:** 에디터에서 뭔가 해달라고 할 때는 **매번 처음 하는 사람에게 설명하듯 전부 다시 적는다.** "지난번처럼", "아까 그 창에서" 같은 표현을 쓰지 않는다. 창을 여는 메뉴 경로(상단 메뉴 → 항목 → 하위 항목), 클릭할 버튼의 위치와 이름, 기대되는 화면 변화, 정상/비정상 판별 기준까지 포함한다. 왜 그 단계가 필요한지도 한 줄 붙인다 — 맥락을 잊은 채 읽기 때문이다.

Unity 고유 용어(asmdef, MonoBehaviour, URP, Test Runner 등)는 나올 때마다 한 줄 설명을 붙인다. 반대로 C#·아키텍처·파일 구조 설명은 눈높이를 낮출 필요 없다.

이 사실이 [[jianghu-core-unity-split]] 의 아키텍처 결정(게임 규칙을 Unity 밖 순수 C# 으로 빼기)을 낳은 직접적 이유다 — 에디터 왕복을 줄일수록 사용자 부담이 준다.
