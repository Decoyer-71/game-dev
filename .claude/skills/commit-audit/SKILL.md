# 커밋 전 감사 — 말한 것이 파일에 있는가

**기억으로 답하지 않는다. 전부 파일을 열어 확인한다.** 이 스킬의 유일한 목적이다.

## 1. 약속 목록을 만든다

이번 작업에서 **하기로 한 것**을 전부 적는다. 빠뜨리기 쉬운 출처:

- 사용자가 확정한 것 (선택지 응답 · "확정" · "그렇게 해")
- 내가 *"~하겠습니다" · "~도 함께 고치겠습니다"* 라고 답한 것
- 측정 후 *"이 값을 조정했다"* 고 보고한 것
- verify·리뷰가 지적해 **고치겠다고 한 것**

## 2. 항목마다 파일에서 확인한다

| 확인 | 방법 |
|---|---|
| 코드 변경 | 해당 상수·함수를 `Grep` 으로 **실제 값** 확인 |
| 문서 역반영 | 정의서·HANDOFF 에서 같은 항목을 `Grep` (`CLAUDE.md` §5-A) |
| **수치 일치** | **문서에 적힌 값 == 코드 상수값** 인지 양쪽을 열어 대조 |
| 테스트 | 새 규칙에 회귀 테스트가 있는가 |

⚠ **가장 자주 나는 사고는 "코드만 고치고 정의서를 안 고친 것"** 과 **"문서에 옛 숫자가 남은 것"** 이다. 실제로 기력소실 세기가 코드 14 · 정의서 12 로 갈라져 있었다.

## 3. 검증을 돌린다

```
D:\Tools\dotnet\dotnet.exe test D:\GameDev\projects\Jianghu\Tools\CoreTests\CoreTests.csproj
```

밸런스 상수를 바꿨으면 **Sandbox 도 다시 돌려** 문서에 적은 측정값이 최신인지 본다.
문서에 옛 측정값이 남아 있으면 그것도 누락이다.

## 4. `git status --short` 로 대조한다

- 바뀌었어야 할 파일이 **목록에 없으면** → 반영 안 된 것이다
- 목록에 있는데 **약속에 없는 파일** → 의도한 변경인지 확인. 아니면 뺀다

## 5. 한 표로 보고한다

```
반영 확인 N건 · 누락 M건

✅ <항목>            <파일:줄>
❌ <항목>            누락 — <무엇이 없는지>
⚠ <항목>            불일치 — 문서 X vs 코드 Y
```

- **누락이 하나라도 있으면 커밋하지 않는다.** 고친 뒤 다시 감사한다
- 고칠 수 없으면 **사용자에게 보고하고 판단을 받는다.** 조용히 넘기지 않는다
- 전부 통과하면 `confirm-sync` 로 넘어간다

## 하지 않을 것

- 코드 품질·설계 검토 (그건 `verify` 와 코드 리뷰의 일)
- 약속하지 않은 개선 착수
- "아마 됐을 것" 이라는 판단 — **열어보지 않았으면 미확인으로 적는다**
