# 확정 즉시 보존 (commit → push)

CLAUDE.md §10 의 실행 절차다. **사용자가 확정한 것은 대화에만 남기지 않는다.**
컨텍스트는 요약되면 사라지지만 커밋은 남는다 — 이 스킬의 존재 이유가 그것이다.

## 언제 쓰는가

**쓴다** — 사용자가 방금 무언가를 확정했고, 그 결정이 파일에 반영된 뒤:
- "승인" / "통과" / "확정" / "채택" / "이대로 가자" / "반영해" / "좋아 그걸로"
- 선택지를 준 뒤 사용자가 한 안을 고른 경우 (AskUserQuestion 응답 포함)
- 규칙·수치·이름을 사용자와 합의해 정의서(`docs/`)에 반영한 경우
- 측정 근거로 상수를 조정하고 그 결과를 보고한 경우 (사용자의 상시 위임 범위)

**안 쓴다**:
- 사용자가 확정한 게 아니라 **다음 단계로 넘어가자**고만 한 경우 ("진행하자", "이어서 해줘") — 진행 지시는 확정이 아니다
- 아직 검토·초안 단계인 산출물 (초안은 **승인받은 뒤에** 커밋한다)
- 테스트가 깨진 채로 있는 상태 — 아래 4단계 참조

## 절차

### 0. ⚠⚠ `commit-audit` 를 먼저 돌린다 (2026-07-31 신설)

*"하기로 한 것이 실제 파일에 있는가"* 를 파일 대조로 검사한다. **누락이 있으면 커밋하지 않는다.**
코드만 고치고 정의서를 안 고친 것, 문서 수치와 코드 상수가 어긋난 것이 이 작업공간에서 반복되는 사고다.

### 1. 무엇이 변했는지 먼저 본다

```bash
git status --short
```

`git add -A` 를 반사적으로 치지 말 것. 목록을 읽고 **이번 확정과 무관한 파일이 섞여 있으면 빼고** 스테이징한다.
`.gitignore` 가 Unity `Library`(1.8GB)·`Temp`·생성 `csproj` 를 이미 막고 있지만, 새 생성물이 목록에 보이면 커밋이 아니라 `.gitignore` 를 고칠 신호다.

### 2. 브랜치를 확인한다 — ⚠⚠ `main` 이면 커밋하지 않는다

```bash
git rev-parse --abbrev-ref HEAD
```

**`main` 에 직접 커밋·푸시하지 않는다**(CLAUDE.md §5-B). `main` 위에 서 있다면 커밋하기 전에 스코프 브랜치로 옮긴다.

| 스코프 | 브랜치 |
|---|---|
| 무공 · 전투 엔진 · Core 로직 · 설계 문서 | `feat/martial-engine` |
| UI · 이미지 에셋 · 사운드 | **별도 브랜치. 만들기 전에 사용자에게 묻는다** |

그 외에는 **현재 브랜치에 그대로 푸시한다.** 브랜치를 새로 만들거나 갈아타지 않는다 — 사용자가 명시적으로 요청했을 때만.
`main` 병합은 **사용자가 "마무리하자" 라고 했을 때만** 한다(§5-B). 확정 하나마다 올리지 않는다.

원격은 `origin` = `https://github.com/Decoyer-71/game-dev.git` (⚠⚠ PRIVATE 저장소, 2026-07-30 실측).

### 3. C# 이 바뀌었으면 테스트를 돌린다

```bash
D:/Tools/dotnet/dotnet.exe test D:/GameDev/projects/Jianghu/Tools/CoreTests/CoreTests.csproj
```

`dotnet` 은 PATH 에 없다. **전체 경로**로 부른다(CLAUDE.md §2).
문서(`docs/`, `*.md`)만 바뀌었으면 건너뛴다.

### 4. 테스트가 깨져 있으면 — 숨기지 말고 같이 커밋한다

빨간 테스트를 **넘기거나 지우지 않는다.** 두 갈래다:

- **고칠 수 있으면** 고치고 나서 커밋한다
- **원인 규명이 남았으면** 깨진 채로 커밋하되 제목에 `(WIP)` 를 붙이고 본문에 **증상과 현재 가설**을 적는다. 사용자에게도 "테스트 N개 실패 상태로 저장했다"고 그 자리에서 보고한다

실패를 조용히 통과시키는 것이 이 프로젝트에서 가장 비싼 실수다.

### 5. 커밋 메시지는 **파일로 넘긴다**

⚠⚠ **`git commit -m "..."` 를 쓰지 않는다** (2026-07-30 실측 사고).
PowerShell 이 따옴표가 든 한국어 인자를 쪼개서 커밋이 깨진다.

```bash
git commit -F "<스크래치패드>/commit-msg.txt"
```

메시지 파일은 **BOM 없는 UTF-8** 로 Write 툴로 쓴다.
⚠⚠ PowerShell `Get-Content`/`Set-Content` 로 한국어 파일을 왕복시키면 **전부 깨진다**(실측). 파일 수정은 Write/Edit 툴로만.

**메시지 형식** — 이 저장소의 기존 관례를 따른다:

```
<한 줄 요약> — <왜 / 그래서 무엇이 달라졌는가>

무엇을 왜 그렇게 정했는지. 사용자와 합의한 내용이면 그 판단 근거까지.
반증·실패한 시도가 있었으면 지우지 말고 같이 남긴다 (§4).
검증은 무엇으로 했는지 (테스트 N개 통과 / 실측값 / 대조한 문서).

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

제목은 한국어, Conventional Commits 접두사(`feat:` 등)를 쓰지 않는다.
`—`(em dash) 로 "무엇을 했다 — 왜/결과" 를 잇는 것이 기존 커밋들의 형태다.

### 6. 푸시

```bash
git push
```

업스트림이 없는 새 브랜치면 `git push -u origin <현재브랜치>`.
**`--force` 는 사용자가 명시적으로 요청하지 않는 한 쓰지 않는다.**

인증이 막히면(`Invalid username or token`) 자격증명을 **대신 입력하지 않는다.**
사용자에게 상황을 보고하고 직접 처리하도록 안내한다. `gh` 는 `D:\Tools\gh\bin\gh.exe` 에 설치돼 있고 인증돼 있다(2026-07-30).

### 7. 한 줄로 보고한다

```
저장 완료 — <커밋 해시> · <브랜치> · 테스트 N개 통과
```

커밋 메시지 전문을 다시 늘어놓지 않는다. 사용자는 방금 그 내용을 확정한 사람이다.

## 자주 밟는 것

| 증상 | 원인 | 대응 |
|---|---|---|
| 커밋 메시지가 잘리거나 깨짐 | `-m` + PowerShell 인자 분해 | `-F` 로 파일 전달 |
| 한국어가 `???` 로 바뀜 | PS `Get-Content`/`Set-Content` 왕복 | Write/Edit 툴만 사용 |
| 거대한 diff | Unity 생성물이 추적됨 | 커밋 말고 `.gitignore` 를 고친다 |
| `dotnet` not found | PATH 미등록 | `D:/Tools/dotnet/dotnet.exe` 전체 경로 |
| 푸시 인증 실패 | 토큰 만료 | 사용자에게 넘긴다. 자격증명을 직접 다루지 않는다 |
