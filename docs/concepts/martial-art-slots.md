## 1. 구상안 원문

`docs/reference-nangman-combat.md` §3·§7 — 참조작(낭만강호) 전투 영상 분석에서 나왔다. 원문 요지:

> 슬롯 수는 인물당 **3칸**이고 **카테고리 고정**이다 — 1번 = 공격무공(초식) · 2번 = 내공 · 3번 = 경공.
> ⭐ **우리 엔진에 이미 같은 카테고리가 있다**(`ArtKind` Attack/Internal/Movement, 내공·경공은 이미 패시브). 즉 필요한 것은 **새 축이 아니라 장착 제한 하나**다.
> ⚠⚠ 이것이 `game-research` 가 지목한 최대 위험을 정면으로 없앤다. 리서치 결론은 *"슬롯을 넣어도 **기대 피해 최대** 자동 선택이 그대로면 슬롯은 장식이 된다"* 였는데, **공격 무공을 1개만 장착하면 고를 것이 아예 없어진다.**
> ⛔ **쿨다운은 분리한다** — 게이팅 축이 둘이 되면 어느 쪽을 손봐도 다른 쪽이 왜곡된다.

### 1-1. 내가 이해한 바

**배운 무공 전부가 전투에 기여하는 지금 구조를, "장착한 것만 기여한다"로 바꾼다.** 공격 1 · 내공 1 · 경공 1.
노리는 것은 둘 — ⓐ 전투 중 알고리즘의 선택을 없애고 **전투 전 플레이어의 선택**만 남긴다 ⓑ *"많이 배우는 것이 언제나 정답"* 이라 결정이 없는 현 구조를 깬다.

### 2-2. ⚠⚠ 실패 사례

**찾지 못했다.** *"슬롯 제한을 넣었다가 실패한 게임"* 에 해당하는 1차 근거를 확보하지 못했다. **없다고 단정하지 않는다.**
⚠ 인접 근거는 하나 있다 — Path of Exile 커뮤니티의 *"자원과 쿨다운을 같이 쓰면 어느 쪽을 손봐도 다른 쪽이 왜곡된다"* 는 통설. **3차 출처이고 1차 개발자 근거는 못 찾았다.** 이 근거로 쿨다운을 분리하기로 한 판단은 유지하되, **근거의 등급을 낮게 본다.**

### 2-3. 장르의 알려진 함정

- **슬롯이 장식이 되는 것** — 알고리즘이 여전히 최적을 고르면 플레이어의 배치는 의미가 없다
- **게이팅 축 중복** — 자원과 쿨다운이 겹치면 밸런싱 손잡이가 서로를 왜곡한다(이 저장소가 쌍雙에서 실측으로 겪었다 · `HANDOFF.md` §4-4)

## 3. 구현 가능성 (§8-2)

### 3-0. ⛔⛔ 먼저 — **이 안의 핵심 논거가 사실과 다르다** (2026-08-05 실측)

구상안은 *"기대 피해 최대 자동 선택을 없앤다"* 를 최대 이점으로 든다. **그런 자동 선택은 없다.**

`CombatResolver.SelectArt` 는 이렇게 점수를 매긴다:

```
score = art.BasePower × PowerMultiplier × HitCount
```

그런데 **형태소 무공은 `BasePower` 가 0 이다**(`MartialArt.cs:152` — `basePower: 0` 하드코딩). 138종 전부 해당한다.
→ 모든 후보의 점수가 **0** 이고, 비교가 `score > bestScore`(엄격 부등호)라 **맨 처음 것만 통과한다.**
→ ⭐ **기력이 충분한 한, 맨 처음 배운 공격 무공만 평생 쓴다.**

**실측으로 확인했다** (임시 진단 테스트, 같은 시드·같은 상대):

| 배운 순서 | 실제로 쓴 무공 |
|---|---|
| `참정`(2자) → `참정독명`(4자) | **참정** |
| `참정독명`(4자) → `참정`(2자) | **참정독명** |

**같은 두 무공인데 배운 순서만 바꿨더니 다른 것을 쓴다.** 순서 의존이다.
⚠ 두 무공의 `Delta.Attack` 이 **둘 다 2.75** 라는 것도 함께 확인됐다(독·명은 공격을 안 준다). 즉 *"더 센 무공"* 의 정의부터가 `BasePower` 로는 표현되지 않는다.

**⚠⚠ 왜 지금까지 안 보였나** — Sandbox 측정 표본과 모든 테스트가 **공격 무공을 정확히 1개씩만** 준다. 후보가 하나면 순서 의존이 드러나지 않는다. §3-2 의 *"측정하지 않는 축은 고장 나도 보이지 않는다"* 의 또 다른 형태이며, 이번엔 **표본이 문제를 가린 경우**다.

→ **이것은 슬롯 구상안의 전제이자, 그것과 독립적인 결함이다.** Phase 3 에서 제자가 무공을 여럿 갖는 순간 표면화된다.

#### ⚠ 두 번째 얼굴 — 레거시 무공이 섞이면 **순서와 무관하게 레거시가 항상 이긴다** (`verify` 실측)

`MartialArt.Technique()`(레거시 팩토리)로 만든 무공은 `BasePower > 0` 이라 점수가 0 보다 크다. 형태소 무공(전부 0)과 한 사람에게 섞이면 **나중에 배워도 레거시가 항상 선택된다.**
⚠ 지금 카탈로그 138종은 전부 형태소 경로라 **현재는 발현되지 않는다.** 다만 `Technique()` 는 여전히 공개 API 이고 테스트들이 쓰고 있으며, `MorphemeCombatTests.레거시_무공과_형태소_무공이_같은_엔진에서_돈다` 가 **혼재를 정상 케이스로 다룬다.**
→ **즉 이 결함은 얼굴이 둘이다** — 형태소끼리는 *순서 의존*, 레거시가 섞이면 *레거시 독식*. 고칠 때 둘 다 봐야 한다.

### 3-1. 비용 판정

| 필요한 것 | 조달 수단 | 비용 | 판정 |
|---|---|---|---|
| **`SelectArt` 결함 수정** | Core C# — 점수식을 `Delta` 기반으로 바꾸거나, 선택 자체를 없앤다 | **가장 쌈** (§9 1행) | **가능 · 선행 필수** |
| 장착 슬롯 데이터 | `Combatant` 에 장착분 필드 추가 · `Arts` 를 "배운 것" 과 분리 | **쌈** — Core 안에서 끝난다 | 가능 |
| 보조 무공 합산 경로 수정 | `Combatant` 의 합산 루프 **11곳**(방어·회피·막기·반격·속도·최대기력·회복·상성·면역 …)이 `Arts` 전체를 훑는다 | **중간** — 넓게 퍼져 있다 | 가능 |
| 측정 도구 갱신 | Sandbox 는 이미 1개씩만 준다 → **변경 불필요** | **0** | 가능 |
| **장착 UI** | Unity 에디터 작업 | **⚠⚠ 가장 비쌈** (§9 마지막 행 — MCP 미연결 + 사용자 Unity 초심자) | **Phase 4 로 미룬다** |
| 콘텐츠 분량 | 없음 — 무공 138종은 이미 있다 | 0 | 가능 |

### 3-1-a. ⚠ 가장 비싼 항목

**Unity 에디터 작업(장착 UI)** 이다. 다만 이건 **Phase 4 로 분리 가능**하다 — Core 에 장착 개념을 넣고 기본값을 *"배운 것 중 첫 번째"* 로 두면 UI 없이도 로직이 성립한다.
**콘텐츠 분량은 0 이다.** 이 안의 좋은 점이며, §9 판정 원칙의 *"콘텐츠 분량이 재미의 핵심인 설계는 신중하게"* 에 걸리지 않는다.

### 3-2. 불가능한 부분과 대안

**불가능한 것은 없다.** 다만 **지금 넣으면 어떤 지표도 안 움직인다** — 측정 표본이 전부 공격 무공 1개라 슬롯 제한이 사실상 이미 적용된 상태다.
→ **효과를 잴 수 없는 변경**이고, 이 저장소가 반복해서 밟은 *"측정 없이 넣은 것"* 이 된다.

## 4. 재미 검토 (§8-3)

### 4-1. 플레이어의 결정은 어디에 있는가

**결정을 만드는 방향은 맞다.** 지금은 보조 무공이 전부 합산되므로 **많이 배우는 것이 언제나 정답**이고, 그건 결정이 아니라 수집이다. 슬롯 제한은 *"무엇을 버릴 것인가"* 를 만든다 — 잘못 고르면 실제로 손해가 나므로 **무게가 있는 결정**이다.

⚠ **다만 지금 상태에서는 결정이 이미 사라져 있다.** §3-0 때문에 공격 무공은 **처음 배운 것만** 쓰인다 — 즉 *"많이 배우면 강해진다"* 조차 공격 축에서는 성립하지 않고, 대신 **"두 번째로 배운 무공은 존재하지 않는 것과 같다"** 는 더 나쁜 상태다.
→ **결함을 고치는 것만으로도 §4-1 의 문제 절반이 해결된다.** 슬롯은 그다음 질문이다.

### 4-2. 결과가 얼마나 빨리·선명하게 돌아오는가

전투가 자동이므로 **결정은 전투 전에 전부 들어간다** — 이 안이 노리는 자리가 정확히 거기다. ✅
⚠ 단 **선명함은 아직 없다.** 장착을 바꿨을 때 무엇이 달라지는지 보여줄 화면이 Phase 4 전까지 없다. 그전까지는 승률표로만 확인된다.

### 4-3. 이 소재여야만 하는 이유가 있는가

⚠ **약하다.** 슬롯 제한 자체는 무협과 무관한 범용 장치다.
다만 **이 프로젝트에서는 형태소 체계와 물린다** — 장착이 1개면 *"이 무공의 네 글자를 어떻게 짜는가"* 가 전부가 되고, 그건 **독문무공 창시**(구상안 핵심 목표)를 전투에 직결시킨다. 여러 개를 장착하면 조합이 희석되어 글자 선택의 무게가 줄어든다.
→ **소재와의 연결은 슬롯이 아니라 형태소 쪽에서 온다.** 슬롯은 그 연결을 **강화**하는 장치다.

### 4-4. 구조적 약점

**전투 중 다양성이 사라진다.** 한 인물이 초식 하나만 반복한다 — 참조작이 실제로 그렇다(영상에서 윤신명은 `성운일검`만 반복). **그게 나쁜지는 플레이로만 확인된다.**
⚠ 그리고 이 프로젝트에는 **아직 플레이할 화면이 없다**(Phase 4 미착수). 즉 **이 약점을 지금은 판정할 수단이 없다.**

---

## 5. 검증할 재미 가설

⏸ 보류이므로 비워 둔다. 채택 시 아래를 출발점으로 삼는다:

> 가설: 무공을 **1개만 장착**하게 하면, 무공 선택(= 형태소 조합)이 전투 결과를 눈에 보이게 바꾼다.
>
> **반증 조건**: 장착을 바꿔도 승률이 ±3%p 안에서만 움직이면 슬롯은 장식이다.

---

## 6. 결론 — 순서를 바꾼다

1. **먼저 `SelectArt` 결함을 고친다.** 슬롯과 무관하게 존재하는 버그이고, Phase 3 에서 반드시 터진다
2. 고친 뒤 **무엇을 고쳤는지에 따라 이 안의 필요성이 달라진다**:
   - *"제대로 된 기대 피해 최대 선택"* 으로 고치면 → 원 논거(*"알고리즘의 선택을 없앤다"*)가 **되살아나고** 이 안이 다시 유효해진다
   - *"애초에 하나만 쓴다"* 로 고치면 → **이 안이 사실상 구현된 것**이고 별도 작업이 없다
3. **Phase 3 에서 재검토한다.** 그전에는 측정 표본이 무공 1개라 **효과를 잴 수 없다**

⚠⚠ **`SelectArt` 를 고칠 때 반드시 함께 확인할 것** (`verify` 권고) — *"`Delta` 기반 점수로 바꾼다"* 안은 레거시 무공의 `Delta` 가 기본값 0 이라 **레거시를 자동으로 밀어낼 가능성이 높은데, 그건 지금과 반대 방향의 편향**이다. 어느 쪽이든 **회귀 테스트로 못박은 뒤에** 고친다 — ⓐ 형태소끼리 순서를 바꿔도 같은 것이 뽑히는가 ⓑ 레거시가 섞였을 때 무엇이 뽑히는가.

⚠⚠ **쿨다운은 이 문서의 범위가 아니다.** 게이팅 축을 하나 더 만드는 별개 결정이며, 근거(3차 출처)도 약하다.

## 7. ✅ 후속 — `SelectArt` 결함 수정 완료 (2026-08-05 같은 날 · 사용자 지시)

§6 의 1단계를 그 자리에서 실행했다. 방향은 **"제대로 된 기대 피해 최대 선택"** 이다.

**고친 방법** — 점수를 새로 짓지 않고 **피해 공식과 같은 식을 쓰게 했다.** `CombatResolver.ArtPower(LearnedArt)` 를 뽑아 `SelectArt` 와 `DamagePerHit` 이 **함께 부른다.**

> ⚠⚠ **한 값을 두 곳에서 따로 계산하면 언젠가 갈라진다.** 이번 결함이 정확히 그거였다 — 피해는 `Delta.Attack` 을 읽는데 선택은 `BasePower` 를 읽었다. 그래서 값을 맞추는 대신 **함수를 하나로 묶었다.**

**함께 고친 것** — 점수식의 `× HitCount` 를 **뺐다.** `DamagePerHit` 이 `/ attempts` 로 나누므로 **타격수는 총 피해를 바꾸지 않는다.** 곱하면 다타 무공을 근거 없이 우대한다. ⚠ 카탈로그는 전부 `HitCount == 1` 이라 수치 영향은 0 이다.

**회귀 테스트 2건** (`SelectArtTests`) — ⓐ 배운 순서를 바꿔도 같은 것이 나가는가 ⓑ 레거시가 섞여도 순서가 아니라 세기로 갈리는가.
⚠⚠ **테스트에 이빨이 있는지 확인했다** — 옛 점수식으로 되돌리면 **2건 다 실패**하고, 고친 코드에서 통과한다. *"공허한 통과가 검증됐다로 읽히는 것"* 을 막기 위한 절차다.

**⚠ 밸런스 영향 0** — `Sandbox --compare` **바뀜 0건 · 같음 575건**. 이 문서 §3-2 가 예측한 *"지금 넣어도 어떤 지표도 안 움직인다"* 가 **그대로 실증됐다.** 측정 표본이 전부 공격 무공 1개이기 때문이다.

⚠ **그래서 슬롯 판정은 그대로 보류다.** 결함이 고쳐졌으므로 원 논거(*"알고리즘의 선택을 없앤다"*)는 되살아났지만, **그 선택이 실제로 일하는 표본이 아직 없다.** Phase 3 이 선행조건이라는 §6 의 결론은 안 바뀐다.
