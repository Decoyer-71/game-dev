## 0. 왜 이 화면부터인가

사용자가 셋 중 **무공 목록**을 골랐다(2026-08-09). 근거는 셋이다:

1. **데이터가 이미 전부 있다** — 무공 138종 · 형태소 88자 · 파서 · 유도 수치. **새로 만들 게임 로직이 0** 이고 Unity 층은 읽어서 그리기만 한다
2. **에디터 작업이 가장 작다**(§9 — 에디터 작업은 *"가장 비쌈 · 사용자만 가능"*)
3. ⭐ **형태소 체계가 눈에 보이는 첫 자리다.** *"이름 넉 자에서 수치가 풀린다"* 는 이 프로젝트의 대원칙(정의서 §0)을 지금까지 Sandbox 콘솔로만 확인했다

⚠ 전투 화면(범위 대가 T 확정에 필요한 것)은 4대4 + 진형까지 그려야 해서 더 무겁다. **이 화면으로 UI 파이프라인(한글 · 런타임 조립 · Core 바인딩)을 먼저 뚫고** 전투 화면은 그 위에 올린다.

## 1. ⚠⚠ 진짜 관문은 한글이었다 — 조사가 한 번 뒤집혔다

`docs-lookup` 이 낸 결론을 `verify` 가 **패키지 소스로 반증**했다. 뒤집힌 것을 남긴다.

### 1-1. ⛔ 기각 — TMP + OS 폰트 런타임 SDF 굽기

```csharp
var osFont = Font.CreateDynamicFontFromOSFont("Malgun Gothic", 32);
var fontAsset = TMP_FontAsset.CreateFontAsset(osFont, 90, 9, GlyphRenderMode.SDFAA, 1024, 1024, AtlasPopulationMode.Dynamic, true);
```

*"에디터에서 폰트를 안 구워도 한글이 동적으로 채워진다"* 는 안이었다. **성립하지 않는다.**

- `CreateFontAsset(Font, ...)` 는 내부에서 `FontEngine.LoadFontFace(font, ...)` 를 부르고, 실패하면 *"Make sure **Include Font Data** is enabled in the Font Import Settings"* 를 남긴다
- `Include Font Data` 는 **에셋으로 임포트된 폰트 파일의 Import Settings** 항목이다. 그런데 `Font.CreateDynamicFontFromOSFont` 가 만든 것은 **OS 폰트 이름만 든 런타임 객체**라 Import Settings 자체가 없다
- → 요구 조건을 **구조적으로** 만족할 수 없는 조합이다

### 1-2. ⛔ 기각 — TMP Essentials 임포트를 코드로 우회

`TMP_Text` 는 새로 만들어질 때마다 `LoadDefaultSettings()` 를 타고, 그 안에서 `TMP_Settings.instance` 를 역참조한다. `instance` 는 `Resources.Load<TMP_Settings>("TMP Settings")` 로 찾는데 **그 에셋을 만드는 것이 바로 Essentials 임포트**다. 없으면 `null` 을 그대로 돌려주므로 **커스텀 폰트를 명시 할당해도 `NullReferenceException` 을 낸다.**

→ **TMP 를 쓰는 순간 임포트(클릭 2회)가 전제조건이 된다.**

### 1-3. ✅ 채택 — 레거시 `UnityEngine.UI.Text` + OS 동적 폰트

```csharp
Font korean = Font.CreateDynamicFontFromOSFont("Malgun Gothic", 16);
text.font = korean;
```

| | |
|---|---|
| **에디터 클릭** | **0회** |
| **커밋할 폰트 파일** | **0개** — OS 폰트를 참조만 한다(라이선스 문제 없음) |
| 근거 | `Font.CreateDynamicFontFromOSFont` 는 Unity 6000.0 에 **존재하고 deprecated 가 아니다**(공식 레퍼런스). `UI.Text` 도 ugui 2.0.0 에서 **`[Obsolete]` 표기가 없다**(패키지 소스 확인) |

⚠ **대가** — `UI.Text` 는 SDF 가 아니라 **확대하면 흐려진다.** 고정 크기 텍스트 목록에는 무해하지만, 나중에 확대/축소가 필요해지면 TMP 로 승격해야 한다.
⚠ **배포 시** — 빌드 대상 PC 에 그 OS 폰트가 없으면 실패한다. `맑은 고딕` 은 Windows 기본 내장이라 위험이 낮지만, **폰트 이름 문자열이 로케일에 따라 다를 수 있다.** 그래서 아래 §4 에 **후보를 순서대로 시도하고 실패를 로그로 남기는** 절차를 넣는다.

### 1-4. ⏸ 보류 — TMP 정식 경로

Essentials 임포트(클릭 2회) + 한글 `.ttf` 를 `Assets/Fonts/` 에 넣고 `Include Font Data` 를 켠 뒤 런타임 `CreateFontAsset`.
**재검토 조건**: 텍스트 확대/축소가 필요해지거나, `UI.Text` 의 렌더 품질이 실제로 문제가 됐을 때.
⚠ 이 경로는 **폰트 파일을 저장소에 넣어야 하므로 라이선스를 먼저 본다** — 맑은 고딕은 재배포 불가라 OFL 폰트(나눔고딕·Pretendard 등)를 받아야 한다.

## 2. 사용자 에디터 작업 — **목표 0회**

§9 가 *"Unity 에디터 작업 = 가장 비쌈 · 사용자만 가능"* 이라 못박았으므로, 이 화면의 설계 기준은 **클릭 수**다.

| 방법 | 사용자 작업 |
|---|---|
| 씬에 Canvas·Text 를 손으로 배치 | ⛔ 수십 회 |
| 프리팹을 만들고 인스펙터로 연결 | ⛔ 수십 회 |
| **빈 GameObject + 스크립트 첨부** | ⚠ 4~5회 |
| ✅ **`[RuntimeInitializeOnLoadMethod]` 로 자동 부팅** | **0회 — Play 만 누른다** |

`RuntimeInitializeOnLoadMethod(AfterSceneLoad)` 는 공식 문서가 *"에디터에서 Play 모드에 들어갈 때도 같은 호출이 보장된다"* 고 명시한다. **씬에 아무것도 없어도 스크립트가 스스로 Canvas·EventSystem·목록을 만든다.**

⚠ **함정 하나 등재** — 도메인 리로드를 끈 상태에서 Play 를 재진입하면 정적 상태가 남아 **중복 생성**될 수 있다. 부팅 시 이미 만든 루트가 있으면 지우고 다시 만드는 가드를 넣는다.
⚠ 입력 시스템 — 이 프로젝트는 `activeInputHandler: 2`(Both, `ProjectSettings.asset:679` 실측)라 구식 `StandaloneInputModule` 도 동작한다. **`EventSystem` 이 씬에 있는지 먼저 찾고 없을 때만 만든다.** 두 입력 모듈을 같은 `EventSystem` 에 동시에 얹지 않는다.

## 3. 화면 내용

**한 화면 · 좌우 2단.** 스크롤은 왼쪽 목록에만 있다.

```
┌─ 무공 138종 ──────────────┬─ 상세 ─────────────────────────┐
│ [계층▾][유형▾][성향▾] 검색 │  마한중참  馬寒重斬              │
│ ─────────────────────────── │  천마신교 · 전승무학 · 검 · 마도 │
│ ▸ 절정검법   강호무학 검    │                                  │
│ ▸ 유독척     소문파  비도   │  이름이 푸는 수치                │
│ ▸ 마한중참   전승   검      │   마(魔) 극한경지 공격+2.5 방무25 │
│ ▸ 만우쾌사   전승   비도    │   한(寒) 수식     치명배율+0.3    │
```

⭐ **오른쪽이 이 화면의 존재 이유다.** 글자 하나하나가 어떤 수치를 넣었는지 보이고, 그 합이 아래에 나온다 — *"수치의 출처는 오직 이름"* 이 화면에서 증명된다.

**⚠ 1단계에서 넣지 않는 것** (범위를 좁힌다)
- 정렬·검색 (필터 3개만)
- 스크롤 관성·애니메이션·색 테마
- 무공 습득·수련 등 **상태를 바꾸는 것 일체** — 이 화면은 **읽기 전용**이다

## 4. 구현 형태

### 4-0. ⛔⛔ 먼저 Core 에 구멍이 하나 있다 — `verify` 가 잡았다

**우측 상세를 그리려면 무공을 다시 분해해야 하는데, 지금 API 로는 상당수가 예외를 던진다.**

- `MorphemeParser.Parse(name)` 의 1인자 오버로드는 `kind = null` 로 도는데, 그건 **접미사에서 종류를 읽는 경로**다
- 접미사가 없는 이름은 **호출자가 `ArtKind` 를 명시해야 한다**
- 그런데 **`MartialArt` 는 자기 `ArtKind` 를 보관하지 않았다** — `MartialArtFactory` 가 계산해 쓰고 버렸다
- **실측 추적**: 시안에 쓴 `마한중참` 조차 `Parse("마한중참")` 로는 *"접미사가 없다"* 로 **`ArgumentException`** 이 난다

⭐ **시안으로 고른 예시가 시안대로는 안 돌아갔다.**

**✅ 실측 확정 — 71종이다** (2026-08-09, 변이 시험). ⚠ `verify` 는 *"129/138"* 로 추정했는데 **틀렸다**: 내공·경공 무공은 이름이 `공`·`결`·`보`·`술` 로 끝나 **접미사를 갖기 때문에** 1인자 경로로도 분해된다. 실제로 깨지는 것은 **접미사가 없는 공격 초식 71종**이다. → **추정치를 그대로 문서에 남기지 않는다.**

**→ 1단계 0번 작업 — ✅ 2026-08-09 완료**
- `MartialArt.Kind` 신설 · `MartialArtFactory` 가 `parsed.Kind` 를 실어 보낸다(상성·범위·열과 **같은 통로**)
- **`MartialArtFactory.Decompose(MartialArt)`** 신설 — 화면은 파서를 직접 부르지 않는다. *"강호무학이냐 아니냐"* 로 갈리는 한 줄이 `TryCreate` 와 **한 곳에만** 있어야 갈라지지 않는다
- 회귀 **4건** · `dotnet test` **239/0/0** · ⚠ 변이(원래 계획대로 1인자 호출로 되돌리기)로 **71종 실패를 실제로 재현**해 시험이 공허하지 않음을 확인

**⭐ 그 과정에서 하나 더 나왔다 — 접미사는 강호무학 전용이 아니다.** `신풍양공`(소문파 내공)도 `공` 이 떨어져 본체가 `신풍양` 3자다. 내공은 `공`·`결`, 경공은 `보`·`술` 로 끝나는 것이 작명 관례이기 때문이다.
→ **상세 화면은 접미사 글자에 *"형태소 아님"* 을 표시해야 한다.** 수치가 없는 글자인데 아무 표시가 없으면 *"이 글자는 왜 기여가 없지"* 가 남는다.

### 4-1. 파일

**Unity 층 4개 · 200~350줄 예상 · Core 는 위 0번 한 줄**

| 파일 | 하는 일 |
|---|---|
| `UiBootstrap.cs` | `[RuntimeInitializeOnLoadMethod]` 진입점. 중복 가드 · Canvas/EventSystem 생성 |
| `KoreanFont.cs` | OS 폰트 후보를 **순서대로 시도**하고 전부 실패하면 **로그로 크게 알린다**. ⚠ 조용히 □ 로 두지 않는다 |
| `MartialListScreen.cs` | 좌측 목록 + 필터. `MartialArtCatalog.All` 을 읽는다 |
| `MartialDetailPanel.cs` | 우측 상세. **Core 가 내준 분해 결과를 그리기만** 한다 — 재분해도 재계산도 하지 않는다 |

**⚠⚠ 이 층은 게임 규칙을 갖지 않는다**(프로젝트 §1-1). Core 를 **읽기만** 하고, 수치를 다시 계산하지 않는다 — 화면이 자체 계산을 시작하면 Sandbox 와 값이 갈린다(이 저장소가 §4-9-6 에서 이미 겪은 병).

**⚠ 테스트** — Unity 층은 `dotnet test` 로 못 돈다(UnityEngine 참조). 그래서 **글자별 기여를 만드는 순수 함수는 Core 쪽에 두고 EditMode 테스트를 붙인다.** 화면은 그 결과를 그리기만 한다.

## 6. ⚠ 무엇이 버려지는가 — 미리 적는다

| | 나중에 |

| `KoreanFont` | ✅ **그대로 쓰인다** — 모든 화면이 한글을 쓴다 |
