### 이 프로젝트의 중심 아이디어 한 문장

**무공명이 곧 데이터다.** 무공을 개별 수치로 만들지 않고 **한자 형태소 조합에서 자동 유도**한다.

```
신환보 = 신(迅 빠르다 → 속도+1) + 환(幻 기만 → 명중+2/공격−0.75) + 보(步 경공 접미사)
```

무공 138개를 각각 조정하는 대신 **형태소 84자**만 잡으면 된다. `../CLAUDE.md` §9 의 "분량=시간" 함정을 회피하고, **이름이 곧 설명**이라 이해 비용도 낮다. 구상안의 핵심 목표(**독문무공 창시**)도 별도 시스템 없이 나온다 — 플레이어가 형태소를 조합하면 그게 자기 무공이다.

**⚠⚠ 파서의 키는 한자가 아니라 한글 한 글자다.** 이 사실 하나가 이 체계의 제약 대부분을 만들었다. 중/重·광/光·성/聖·공/功·산/散 이 한글을 선점해서 中·廣·星·空·山 을 쓸 수 없다. **새 글자를 넣기 전에 반드시 한글 충돌부터 확인할 것.**

### 3-2. 전투 엔진 — `Core/Combat/`

**연결된 축** ✅
- **위력** — `art.Delta.Attack` (형태소 무공) / `BasePower` (레거시). 분기가 남아 있다

  ⚠⚠ **숙련·성향 배율을 곱하지 않는다** — 곱셈 누적 금지(§5). 규칙 전문은 정의서 §1-3-a

|---|---|

| 캐릭터 레벨 | 만렙 고정 |

### 4-2-k. ✅ 자를 고치고 반초를 재설계 — **3자 목표 달성** (2026-08-01) · 남은 위반 2건

§4-2-j 가 *"자가 고장 났다"* 를 밝힌 뒤, **자를 먼저 고치고 그 자로 반초를 재설계**했다. **목표 지표는 달성됐다.**

#### ① 자 재정의 — 짝지음(paired) + 상대 조건

무엇이 잘못됐었나: 경계가 **단일 시드 블록 실측치 ±0.05** 인데 σ 는 2%p 였고, **기준선이 만족한 적 없는 절대 구간**을 후보에게 요구했다(탈 52.5 는 이미 "무의미" 로 기록돼 있었다).

고친 방식:
- **모든 "유지" 조건을 기준선 대비 상대 조건으로.** 후보와 기준선을 **동일 시드 블록**에서 재고 그 차이를 본다 — 공통 난수라 잡음이 대부분 상쇄된다
- 판정은 블록별 통과/실패가 아니라 **차이의 평균 ± SE(= sd/√7)** 와 t 값으로. 악화 = 방향이 나쁘고 `|평균| > 2·SE`
- **목표 조건(전락률)만 절대**로 두되 참값 기준, 여유 ≥ 2 SE
- 시드 블록을 **겹치지 않게** 바꿨다: `0 / 400 / 800 / 1200 / 1600 / 2000 / 2400`(최대 표본이 400전이므로 400 간격이면 무겹침). 옛 집합 0/200/400 은 400전 지표에서 서로 50% 겹쳐 σ 를 약 2.4% 과소평가했다

✅ **기준선 자가검사 통과** — `(0,3,0)` 이 새 자로 **유지 조건 전부를 자기 자신에 대해 통과**한다. 실패는 애초에 만족한 적 없는 목표 조건(전락률 0.00)뿐이다.

⚠⚠ **그 과정에서 회귀 테스트도 시드 민감하다는 것이 드러났다.** 시드 shim 을 넣어 7블록에서 돌리니 **저장소 기본값이 오프셋 400 에서 1건 · 800 에서 3건 실패**한다:

|---|---|---|

| OFF800 | `기력이_마르면_평타로_전환된다` | 단일 시드 |
| OFF800 | `기력소실은_상대를_평타로_민다` | 0.480 vs `>0.5`, 100표본 σ≈5%p |
| OFF800 | `상태이상_일곱_글자가_전부_넣을_이유를_갖는다` | 같은 측정·같은 원인 |

→ **회귀 조건도 "기준선 대비 신규 실패 0" 으로 상대화해야 한다.** 그리고 **이 4건은 표본을 늘려야 할 테스트**다.

#### ② 반초 재설계 — 계수를 델타가 아니라 **최종값**에

§4-2-j 의 결함 3건은 **`ArtStatDelta * p` 가 델타 기여만 깎았기 때문**이었다(엔진의 모든 축이 `상수 기저 + 델타 기여` 구조). 계수를 **그 행동의 최종값**에 곱하도록 바꿨다:

| 축 | 곱하는 지점 |
|---|---|
| 피해 | `DamagePerHit()` 반환값(타격당 최종 피해), 하한 `MinDamagePerHit` |
| 명중 | `hitChance` **클램프 후** |
| 치명률 | `critChance` 클램프 후 |
| 상태이상 | `Clamp(Base + points + chanceBonus, 0, 100)` **합산·클램프 후** |
| 반격 | 반격이 반초를 골랐을 때 그 피해에도 |

**곱하지 않는 것**: 치명 **배율**(배율은 "터지면 몇 배" 라는 모양이고, 피해가 이미 P% 라 치명 분기도 정확히 P% 다. 배율까지 곱하면 그 분기만 **P²** 가 되어 이름이 다시 거짓말한다) · 상대의 회피·막기 · 성향 변동폭 · 상태이상 세기/지속(무공별로 다르지 않은 상수) · 내상 · 타격 수 · 상시 축.

**결함 3건 해소 실측** (공격 초식 54종 × 60시드, P=70):

| | 옛 구현 | **새 구현** | 이름이 약속한 값 |
|---|---|---|---|
| 실효 명중비 | **1.021 (역전)** | **0.692** | 0.70 |
| 명중당 피해비 | 0.902 | **0.678** | 0.70 |
| 상태이상 부여비 | 0.958 | **0.748** | 0.70 |
| 반초가 원 초식보다 센 무공 | **6 / 54** | **0 / 54** | 0 |
| 그중 공격합 음수 | **5 / 6** | **0 / 6** | 0 |

⚠ **음수 공격합 문제가 별도 하한 없이 사라졌다** — 피해의 출처가 최종값이라 `×p (p<1)` 는 구조적으로 원본을 넘을 수 없다.

⚠⚠ **이름의 정확한 뜻**: "반초는 초식의 P%" 는 **축별로** P% 라는 뜻이다. 명중과 피해가 각각 P% 이므로 **기대 피해는 P²** 다(P=98 → 96%). 표기를 어떻게 할지는 미확정.

⚠⚠ **P < 80 이면 반초가 평타보다 약하다** (실측 교차점). 원인은 `totalPower = Stats.Attack + Delta.Attack × 배율` 인데 만렙 `Stats.Attack = 8` 이 형태소 공격합(평균 1.5~1.65)을 압도하는 것 — **평타가 이미 초식의 약 2/3 위력**이다. 옛 구현이 "부드러워" 보였던 이유가 정확히 델타만 깎았기 때문이다.

### 4-2-i. ⚠⚠⚠ 형태소 가치까지 열어도 해가 없다 — **시드 과적합을 잡은 사건** (2026-08-01)

**그런데 해가 아니었다.**

`verify` 가 하네스에 **시드 오프셋**(`JIANGHU_SEED_OFF`)을 추가해 7개 시드 블록으로 재채점했다:

|---|---|---|

**조건은 `≥ 10`. 참값이 9.999 다 — 하한 위에 있는 게 아니라 하한에 걸터앉아 동전을 던지고 있었다.** 다른 시드에서는 **계층대리가 뒤집히고**(3자가 4자를 이김) **상태이상 불변식 4건이 깨져 회귀가 159/163** 이 된다. 163/163 은 상수의 성질이 아니라 **시드 1..200 의 성질**이었다.

모든 구속 조건의 여유가 **자기 측정 잡음의 1σ 미만**이었다(0.6~0.8σ).

⚠⚠ **§4-2-g 가 같은 `(6,2,4)` 조합에 대해 이미 같은 판정을 내렸다** — *"여유가 측정 노이즈보다 작아 재현되지 않는다."* 이번엔 잡음이 유리한 쪽으로 떨어졌을 뿐이다.

손잡이를 끊어 재 보니 **상태이상 세기를 올려 불변식을 살리는 행위가 곧바로 전락률을 하한으로 민다**:

| (6,2,4) + 안 B 상태이상 | **10.02** | ✅ |

상태이상이 세지면 **전투가 빨리 끝나고, 전투가 짧으면 기력이 덜 마른다.** 두 조건이 **같은 손잡이의 반대편**에 매달려 있어 어떤 격자 탐색으로도 여유가 생기지 않는다.

#### ⚠⚠ 아무도 보지 않던 손해 — 형태소 5개가 새로 죽는다

`verify` 가 형태소 4축 전수를 재서 찾았다:

| 글자 | 기준선 | 안 A |
|---|---|---|
| **계(戒)** | 54.50 | **45.25** |
| **야·암·한** | 52.50 | **47.75** |
| **뇌(雷)** | 55.50 | **49.25** |

**"넣으면 손해" 인 형태소가 2개 → 7개로 늘어난다.** 원인은 내상이다 — 평타로 전락하면 형태소 보너스가 통째로 사라지므로 **기력 압력이 모든 선택 형태소의 한계 가치를 함께 깎는다**(수식 축 전체가 −5.75~−8.50 균일 하락).

⚠⚠ **회귀 163건이 이걸 전혀 못 잡는다.** `Assert.Greater(rate, 0.5)` 불변식은 **상태이상 7자에만** 걸려 있고 나머지 30여 형태소에는 같은 보호 장치가 없다. → **선택 형태소 전반에 "넣으면 손해가 아니다" 불변식을 넣을 것.**

#### 부수로 드러난 것

- **`대문파 vs 소문파` 가 기준선부터 48.89 로 계층 역전 상태다.** 조건표에도 채점표에도 이 항목이 없어 아무도 보고 있지 않았다
- **`QiCostBase = 6` 은 정의서 §1-1-a 의 비례식을 깬다.** 2자 10 · 3자 12 · 4자 14 라 4자/2자가 **1.40**(정의서 2.00). §4-2-g 가 `계수=1` 안(1.18)을 **바로 이 사유로 탈락**시켰으므로 같은 잣대를 대야 한다
- ⚠ **탈(奪) 18 이 "이름이 성능을 거짓말한다" 는 우려는 기각됐다.** 초식 1회 비용 대비로는 기준선 1.56회 봉인 → 1.50회로 **오히려 약하고**, 엔진 주석이 그 세기를 설계 의도로 명시하고 있다. 분모를 최대기력으로 잡은 것이 잘못이었다

#### ⚠ 정정 — 유형 격차 "11.0%p" 는 근거 없는 값이다

### 4-2-h. ⏸ 내상(內傷) 안 — 설계 완료 · **계층 축을 깨서 보류** (2026-08-01)

기력 축을 살리는 안으로 **"피격 시 기력이 정액으로 준다"** 를 설계했다. 사용자가 방향을 승인했고 `verify` 가 조건부 채택을 냈으나, **뒤에 계층 축 위반이 드러나 보류**한다.

**규칙** — 한 행동에서 한 대라도 명중하면 피격자 기력 `−QiLossWhenHit`. 행동당 1회(타격당 아님) · 빗나감·회피는 없음 · 막기는 있음 · **반격은 없음**(명중 판정 자체가 없어 100% 발동이 된다) · 지속 피해는 없음 · 평타도 준다.
⚠ **이름**: "호신강기" 를 버렸다 — 강기는 *피해를 막는 보호막*을 함의하는데 이 메커니즘은 피해를 전혀 줄이지 않는다. 방어관통 160% 와 같은 형태였다. 내상은 *"맞으면 기가 흐트러져 **기력**이 준다"* 다(내공이 아니다 — 내공은 무공 카테고리 이름이다).

**`QiLossWhenHit = 6` 실측** — 4자 전락률 17.2% ✅ · 권 유형 37.0 → **46.0** · 탈(奪) 51.0 → **55.5**(무의미 탈출) · 전투 11.4 → 12.2턴 · 무승부 0 · **회귀 163/163**(지금 건너뛰는 2건이 진짜 통과로 승격). X=7 부터 회귀 3건이 깨져 **6이 상한**이다.

**⚠⚠ 보류 사유 — 계층 대리가 무너진다.** 3자 vs 4자가 **3성 50.25 · 6성 50.25 · 10성 49.75** 다(기준선 39.2 → 사실상 동전던지기). `verify` 가 직접 재측정해 확정했다.
→ **처음 "채택 가능" 판정을 낸 verify 가 이 축을 재지 않았다.** 전락률·유형·탈·회귀만 쟀다. **판정 기준에 넣지 않은 축은 통과 판정에 포함되지 않는다** — §7 지뢰(*"민감도표에 없는 카테고리는 죽어도 안 보인다"*)가 **검증 절차 쪽에서** 재발한 사례다.

⚠ 값을 6 아래로 내리면 계층 축은 살겠지만 전락률이 목표(10%) 아래로 떨어진다. **압력과 계층이 여기서도 상충한다** — §4-2-g 와 같은 벽이다.

### 4-2-g. ⚠⚠ 3자 압력 문제 — 572조합 전수 실측 결과 **기력 축에는 해가 없다** (2026-08-01)

§4-2-d 로 기력 축이 죽은 것을 확인한 뒤, 살리는 방법을 찾다가 **3자(소문파 계층)에는 압력을 걸 수 없다**는 벽에 부딪혔다. 아래는 전부 **실측**이며 `verify` 가 하네스를 독립 재빌드해 기준선 5개를 소수점까지 재현했다.

#### 문제의 닫힌 형태

```
A = 최대기력/전투턴 + 회복 − 추가압력      (턴당 가용 기력)
전락률 ≈ 1 − A / C                        (C = 초식 1회 소모)
```

목표 10~30% 는 `A ∈ [0.7C, 0.9C]`. 현재 `C = 개수 × 3` 이라 **3자는 A ∈ [6.3, 8.1] · 4자는 A ∈ [8.4, 10.8]** 을 요구하는데 **A 는 둘이 공유하는 값이라 구간이 겹치지 않는다.**
→ **최대기력·회복·내상을 어떻게 조합해도 둘을 동시에 넣을 수 없다.** C 의 구조를 바꿔야 한다.

`C = 기본 b + 개수 × 계수 k` 로 쪼개면 겹침 조건은 **`b ≥ 0.5k`**, 조정 여유는 **`0.2b − 0.1k`** 다.

#### 그런데 다른 곳이 막는다 (572조합 전수)

기본 0~12 × 계수 1~4 × 내상 0~10 을 전수 실측했다. **전락률 창은 실제로 열린다** — 분석은 맞았다. 막는 것은 세 제약의 충돌이다:

1. `기력이_마르지_않는_무공은_전락률이_0_이다` → **2자 전락률 == 0.00 정확히**
2. 상태이상·동상·형태소 공격합 3건 → **3자가 2자를 이겨야 한다**
3. 목표 → **3자 전락률 ≥ 10%**

⚠ **"논리적으로 동시 성립 불가" 는 부정확한 표현이다.** 형식적으로 통과하는 조합이 3개 있었다((0,4,4)·(3,3,4)·(6,2,4)). 그러나 **그 여유가 측정 노이즈보다 작아** 실제 회귀에서 재현되지 않는다 — `verify` 가 셋 다 직접 돌려 **163건 중 2~3건 실패**를 확인했다.

**원인: 세 번째 형태소의 한계 가치가 너무 작다.** 압력 0 에서 독 +1.5%p · 빙 +1.0%p · 탈 +1.0%p(200시드). ⚠ 이 크기는 그 표본의 σ≈3.5%p 보다 작아 **통계적으로 0 과 구별되지 않을 수 있다.** 정식 도구(400전)로는 독 53.8 · 빙 53.8 · 탈 52.5 다.
**163/163 을 유지하는 3자 전락률 상한은 실측 약 0.65% — 목표 하한 10% 와 15배 차이다.**

#### 가장 아까운 탈락

| (기본,계수,내상) | 회귀 | 2자 | 3자 | 4자 | 탈락 사유 |
|---|---|---|---|---|---|
| **9,1,5** | **162/163** | 9.30% | 15.79% | 21.50% | **2자 전락률이 0 이 아님** 1건만 실패. 나머지 전 지표 통과 |
| 6,2,4 | 161/163 | 0.00% | 11.02% | 23.18% | 3자>2자 불변식 2건 |

⚠ `계수=1` 계열은 C가 11/12/13 이라 **"형태소 개수가 곧 비용"(정의서 §1-1-a)이 사실상 소멸**한다.

#### 부수로 뒤집힌 예측 하나

*"기본소모는 2자 강호무학을 가장 세게 때린다"* 고 예측했으나 **부호가 반대였다** — 소문파 vs 강호가 60.83 → **55.96**(기본3) 으로 격차가 **좁아진다.** 2자는 명목 비용이 올라도 회복 10 을 못 넘어 **여전히 전혀 마르지 않고**, 3·4자만 실제로 말라 힘을 잃기 때문이다.
→ 일반화: **명목 비용과 실효 압력은 다르다.** 압력은 "얼마를 내는가" 가 아니라 **"회복선을 넘는가"** 로 생긴다.

### 4-2-c. ⚠ 계층 역전 해소 — 기력 소모 상수 4 → 3 (2026-08-01) · **대가가 있었다**

계층은 곧 형태소 개수인데, 회복 10 기준 **턴당 순기력이 2자 +2 / 3자 −2 / 4자 −6** 이었다. 네 번째 형태소가 주는 능력이 기력 비용을 못 갚아 **글자 수만 바꿔 재면 3자가 4자를 이겼다**(51.2 / 50.5 / 52.8).

**상수 4 → 3** 으로 6/9/12(순기력 +4/+1/−2)가 되어 해소됐다:

| 대결 | 전 | 후 |
|---|---|---|
| 2자 vs 4자 | 48.0 | **38.0** |
| **3자 vs 4자** | **52.8** ⚠ | **39.2** ✅ |
| 대문파 vs 강호무학 | 54.7 | **58.8** |

⚠⚠ **회복(10)·최대기력(50)을 올리는 안은 `verify` 가 막았다.** 그쪽은 기력소실 형태소 탈(奪, 세기 14)이 기대는 *회복과의 격차*(−4)를 줄여, **최대기력을 50→80 으로 올렸다가 탈이 46.5% 로 죽어 되돌린 사례**(§5)를 규모만 바꿔 반복한다. 소모 상수는 그 격차를 건드리지 않는다.
→ 일반화: **같은 결과를 내는 손잡이가 여럿일 때, 다른 축이 무엇에 기대고 있는지로 고른다.**

⚠⚠ **그런데 이 변경이 유형 축을 깼다 (2026-08-01 발견).** 상수 4 → 3 은 기력 압력을 없애 **평타 전락률을 0% 로 만들었고**(§4-2-d), 그 결과 권(拳)의 유형 특성(기력 소모 −100%)이 통째로 무의미해졌다 — 유형 격차 **7.4%p → 21.8%p**, 권 **50.2 → 38.4**.
그리고 `verify` 가 막았던 "회복·최대기력 인상" 이 탈(奪)을 죽인다는 논리는, **소모 상수를 내리는 것도 같은 결과를 낸다**는 사실을 보지 못했다 — 탈은 상수 4 에서 54.5(살아 있음), 상수 3 에서 52.5(무의미)다.
→ **보정된 일반화: 그 손잡이가 *다른 축의 존재 조건*을 지우지 않는지까지 본다.** 압력을 소비하는 축(권·탈·내공)은 압력이 0 이 되면 크기로 갚을 방법이 없다 — 권의 −100% 는 이미 상한이라 더 올릴 수도 없다(방어관통 160% 와 같은 자리).

⚠ **대문파 vs 소문파는 48.9% 로 여전히 50 아래다.** 대문파 44종 중 4자가 39종인데도 그렇다 — 남은 원인은 계층이 아니라 **계층 내 격차**(36~82%p)다.

### 4-2-b. ⚠⚠ 유형(무기) 재조정 (2026-07-31) — **결과가 무효화됐다**

> **⚠⚠ 아래 "결과" 표는 기력 상수 4 시절 값이다.** 다음 날 상수를 3 으로 내리면서(§4-2-c) 권이 죽어 **격차 7.4%p → 21.8%p** 가 됐다. 조정의 *방향*(종류는 그대로, 크기만 맞춘다)은 여전히 유효하지만 **크기는 다시 잡아야 한다.**
> ⚠ 그리고 이 표의 측정법 자체에도 한계가 있다 — §4-2-e 참조.


대문파 44종 순위표를 열어 보니 **상위 6종이 전부 검(劍)** 이고 하위는 권·비도였다.

**유형 민감도**(같은 무공을 다섯 무기로 들고 400전)를 처음 재 봤더니 **검 89.1% 대 나머지 37~42%** 였다. 같은 무공인데 무기만 바꿔 이만큼 갈리면 *"무공 조합이 전투를 바꾸는가"* 라는 가설 자체를 무기가 덮는다.

원인은 다섯 특성의 **실효값이 전혀 달랐던 것**이다. 사용자 확정 방향은 **"종류는 그대로, 크기만 맞춘다"**:

| 유형 | 특성 | 조정 | 왜 |
|---|---|---|---|
| **검** | 명중 | **25 → 7%p** | 항상·모든 타격에 걸린다. 명중 형태소 5점어치였다 |
| 창 | 선공 + **속도** | 25 유지 · **속도 +2 신설** | 선공은 전투당 1회뿐. 추가 행동이 속도 기준이라 창 숙달이 안 들어갔다 |
| 도 | 방어관통 | **70 → 100%** | 상대 방어가 3~7 뿐이라 70%로는 깎을 것이 거의 없었다. ⚠ 100 이 물리적 상한이다 |
| 권 | 기력소모 | **−50 → −100%** | 회복 10 이 3자 무공을 감당해 잉여였다 |
| 비도 | 상태이상 | **+30 → +50%p** | 상태이상 형태소를 넣은 무공에서만 값을 한다 |

**결과 (400전 · 무공 10성) — ⚠⚠ 왼쪽은 상수 4, 오른쪽이 현재(상수 3)**

| 무공 | 검 | 창 | 도 | 권 | 비도 |
|---|---|---|---|---|---|
| 참정 (2자) | 56.1 | 60.4 | 49.9 | 41.4 | 41.4 |
| 참정독 (3자·상태이상) | 53.9 | 58.7 | 46.2 | 39.6 | 48.1 |
| 참정독명 (4자) · **상수 4** | 54.5 | 50.4 | 47.1 | **50.2** | 47.1 |
| 참정독명 (4자) · **상수 3 = 현재** | 52.8 | **60.2** | 44.8 | **38.4** ⚠⚠ | 45.1 |

**격차 51.9%p → 7.4%p 였다가 상수 변경으로 다시 21.8%p 가 됐다.** 2자·3자 행이 상수와 무관하게 같은 것에 주목할 것 — **기력이 마르는 4자에서만 갈린다.** 그게 권의 특성이 4자에서만 존재한다는 증거다.

⚠ 이 조정이 **다른 모든 축을 함께 눌렀다**는 관찰은 여전히 유효하다 — 무공형태 13.7 → **9.4%p**, 자연속성 화 66.5 → 59.5, 상태이상 전부 53.8~57.5. 그 축들은 2·3자 비교라 상수의 영향을 안 받는다.

### 4-2-e. ⚠⚠ 유형 민감도표가 못 보는 것 (2026-08-01)

**이 표는 같은 무공명(`참정`=베기)을 다섯 무기에 그대로 얹어 잰다.** 그런데 실제 데이터에서는 **유형이 공격방식을 사실상 강제**한다 — 공격 초식 71종 전수:

| 유형 | 종수 | 공격방식 | 공격 시작값 |
|---|---|---|---|
| 검 | 19 | 베기 17 · 찌르기 2 | **2.0** |
| 도 | 12 | 베기 12 | **2.0** |
| 창 | 13 | 찌르기 13 | 1.5 |
| **권** | 17 | 때리기 17 | **1.0** |
| **비도** | 10 | 던지기 10 | **0.5** |

**69/71 이 1:1 이다.** `ArtCompositionRule` 은 이 결합을 강제하지 않는다(`Discipline` 을 인자로 받지도 않는다) — 순수한 **작명 관행**이다. 권법에 '참(베기)' 을 쓰면 이름이 거짓말이 되니까 아무도 그렇게 안 지었다.

→ 그래서 권·비도는 유형 특성 이전에 **공격 1.0 / 0.5 에서 출발**한다(검·도는 2.0). 공격 1점이 승률 약 36%p 인 스케일에서 1.5점 차이다. **"최하위는 늘 권·비도" 의 구조적 원인이 여기 있고, 유형 민감도표는 공격방식을 고정하므로 이 몫을 계상하지 않는다.**

⚠ 다만 이 표가 *"권·비도가 약하다"* 를 아예 못 본다는 뜻은 아니다 — 현재 값에서도 권 38.4 로 이미 최하위다. 못 보는 것은 **거기에 공격방식 격차가 추가로 얹힌다는 크기**다.

⚠⚠ **권·비도는 조건부로 남겨 뒀다** — 권은 4자에서 51.1%, 비도는 상태이상 무공에서 47.0% 로 살아난다. *"비싼 무공을 끊김 없이 쓴다"* 와 *"암기에 독을 바른다"* 가 곧 그 정체성이기 때문이다.
→ **대신 데이터가 그 조건을 맞춰야 한다.** 권 문파의 무공은 4자여야 하고, 비도 문파의 무공은 상태이상 형태소를 가져야 한다. 아직 확인 안 했다.

⚠ 앞서 *"권법이 다단이 아니다"* 라고 적었던 것은 **오독**이다. 타격 횟수는 유형이 아니라 **문파 특징층**(정의서 §6-3, '매우'/'극히', 문파당 1회) 소관이며 그 층이 미구현이라 138종 전부 1타다.

## 5. ⚠⚠ 밸런싱에서 실제로 배운 것 (다시 밟지 않기 위해)

이 절이 이 문서에서 가장 값나가는 부분이다. 전부 **측정으로 얻은 것**이다.

**기력 회복이 0이면 전투가 성립하지 않는다** (2026-07-30)
4자 무공 기준 3턴 만에 기력이 말라 평타(피해 1)로 전락 → **전원 무승부**. `BaseQiRegen` 을 2 → 10 으로 올려 해소했다.
→ 부수 효과가 설계적으로 좋다: **내공 형태소를 배워야 목표 전락률에 든다.** 내공의 존재 이유가 수치에서 저절로 생겼다.

**명중이 상한에 포화하면 그 축이 죽는다** (2026-07-30)
수식 12자 승률이 **0%** 였다. 원인은 무공이 약해서가 아니라 `85 + 검숙달 25 = 110 → 99 클램프` 라 명중 형태소를 더해도 아무 변화가 없었던 것. `BaseHitChance` 를 85 → 65 로 내려 해소.

**전투가 길어지면 정사마 편차 정체성이 사라진다** (2026-07-30)
사파(편차 ±5%)와 마도(±35%)의 결과 일관성 차이가 안 나왔다. 원인은 테스트가 체력 600 표적을 써서 **24턴**이 걸린 것 — 턴 단위 분산이 큰 수의 법칙으로 평균화된다. 실제 전투는 **9턴**이다.
→ **목표 8~15턴은 편의가 아니라 성향 설계의 성립 조건이다.** 이 범위를 벗어나게 만드는 변경은 정체성을 지운다.

**⚠⚠ 배율축은 그것이 걸리는 확률이 낮으면 통째로 죽는다** (2026-07-31)
치명배율 형태소(+0.3)를 엔진에 붙였는데 승률이 **50.0%**, 즉 안 붙인 것과 같았다. 값이 작아서가 아니라 **기본 치명률이 10% 라 타격 90% 에는 배율이 닿지 않기 때문**이다 — `+0.3 × 10% = 평균 +3%`.
→ 일반화: **확률 × 배율 구조에서는 두 축을 따로 보면 안 된다.** 배율 형태소의 값은 *그 확률과 곱한 기대값*으로 평가해야 한다. 명중이 상한에 포화해 죽은 것(위)과 증상은 다르지만 **원인은 같다 — 형태소 값이 아니라 환산 구조**.

**⚠⚠ 갱신되는 지속효과는 '지속'이 아니라 '상시'다** (2026-07-31)
출혈 세기를 2로 붙였더니 민감도 **70~76% = 지배적**이었다. 세기가 커서가 아니라 **부여확률 40% 로 매 턴 갱신되어 사실상 꺼지지 않았기 때문**이다. 3턴 지속이라는 표기와 실제 체감이 전혀 달랐다.
→ 일반화: **지속 × 세기가 아니라 `세기 × 유지율`로 평가한다.** 갱신을 허용하는 순간 지속 턴수는 상한이 아니라 **재부여 실패까지의 유예**가 된다. 화상에서 갱신 자체를 끊은 것이 이 인식의 결과다 — 세기를 깎아 맞추면 *"유지될수록 아프다"* 는 성격까지 같이 사라진다.

**⚠⚠ 받는 피해 −X% 는 주는 피해 +X% 보다 값이 크다** (2026-07-31)
무공 방어를 처음 이었을 때 방(防) 형태소 하나로 **승률 100%** 가 나왔다. 뺄셈 공식에서 형태소 방어 +2 에 숙련 배율이 곱해져 −4.3 이 되고, 타격이 7~8 이니 상대 공격의 절반이 지워진 것이다. 회피도 정의서 값(15%p)을 그대로 넣으니 **77~80%** 였다.
→ 일반화: **공격축과 방어축을 같은 크기로 넣으면 안 된다.** 1:1 전투에서 방어는 내 수명을 늘리면서 상대 수명은 그대로 두므로 같은 %라도 승률 기여가 더 크다. 설계안 §1-D 는 정반대(*"방어의 상대가치가 붕괴한다"*)를 걱정했는데 **틀렸다** — 그 표가 산술이었고 승률로 환산된 적이 없어서다. ⚠ 산술로 세운 우려는 측정 전까지 가설일 뿐이다.

**⚠⚠ 정수 반올림이 밸런싱의 최소 눈금이다** (2026-07-31) → §4-1-b 참조.
타격이 7~8 인 스케일에서는 12% 미만의 효과가 **통째로 사라진다.** 상수를 고쳐도 승률이 49.8% 에서 꿈쩍 않다가 어느 지점에서 66% 로 건너뛴다. 눈금 배수 5 를 넣어 해소했다.
→ 일반화: **밸런싱이 막혔을 때 원인이 값이 아니라 표현력일 수 있다.** 값을 계속 흔들기 전에 "이 차이가 표현될 수 있는가" 를 먼저 본다.

**⚠⚠ 성장 요소를 늘리면 다른 축의 존재 이유가 사라질 수 있다** (2026-07-31)
만렙 기력을 50 → 80 으로 올리자 **11턴 전투 동안 기력이 마르지 않게** 됐고, 그 순간 ⓐ 기력 고갈 → 평타 전락이라는 전투의 드라마와 ⓑ 기력소실 형태소 탈(奪)이 **동시에 죽었다**(46.5% = 넣으면 손해). 되돌렸다.
→ 일반화: **캐릭터 성장과 무공 축이 같은 자원을 건드리면 한쪽이 다른 쪽을 지운다.** 최대기력은 내공 무공의 축이므로 캐릭터가 겸하지 않는다. 새 성장 요소를 넣기 전에 *"이게 어느 무공 축과 같은 자원을 만지는가"* 를 먼저 묻는다.

**⚠⚠ 유도한 값과 원본 값이 어긋나 있었다** (2026-07-31)
`MartialArt.Tier` 가 **문파명에서 계층을 유도**하고 있었다. 그런데 대형세력 4곳은 `SchoolCatalog` 에 없어서 **16종이 전부 강호무학으로 분류**됐다 — 승률표의 강호무학 그룹 11종 중 6종이 실제로는 대문파급 4자 무공이었고, 그래서 *"계층 간 우위가 없다"(전부 ~51%)* 는 결론이 나왔다. **카탈로그는 처음부터 정확한 계층을 알고 있었는데 그걸 버리고 다시 유도하고 있었다.** 고치니 소문파 vs 강호무학이 51 → **57.0%** 로 돌아왔다.
→ 일반화: **이미 아는 값을 버리고 유도하지 않는다.** 유도는 원본이 없을 때의 차선이고, 그 유도가 실패하는 경우(여기서는 '문파가 아닌 소속')는 조용히 기본값으로 떨어진다.

**⚠⚠ 크기를 반영하지 못하는 축은 통화가 될 수 없다** (2026-07-31)
정의서대로 속도를 '행동 순서' 로만 이었더니 **±2 든 ±5 든 승률이 소수점까지 같았다.** 선공은 비교라서 이진값이고, 그러면 사전 수치를 아무리 만져도 그 축을 사고파는 형태소는 균형에 들어오지 않는다. **추가 행동 확률**을 붙여 연속축으로 만든 뒤에야 쾌(25.7%)가 살아났다.
→ 일반화: 새 축을 이을 때 *"이 축은 값이 커지면 결과도 비례해 커지는가"* 를 먼저 확인한다. 아니면 그 축은 밸런싱 대상이 아니라 **깃발**이다.

**⚠⚠ 축의 단위가 다른데 숫자만 맞추면 안 된다** (2026-07-31)
무공형태 5종을 전부 `±2` 로 대칭시켜 뒀는데 실측 승률이 6.3~86.7% 였다. 공격 1점 ≈ 36%p · 명중 1점 ≈ 13%p · 속도 1점 ≈ 15%p 라 **같은 숫자가 전혀 다른 값어치**였다.
→ 일반화: **페널티가 비싼 쪽에 보상을 덜 준다.** 대칭적으로 보이는 표가 실제로는 비대칭이며, 대칭은 숫자가 아니라 **측정된 순 가치**에서 맞춰야 한다.

**⚠ 극값(최대−최소)으로 편차를 재지 않는다** (2026-07-31)
`사파는_전투_결과가_가장_일정하다` 가 미스 한 번에 흔들려 동률이 반복됐다. 재려던 것은 성향 편차인데 실제로는 **명중 운**을 재고 있었다. → 표본 60 → 300, 극값 범위 → **표준편차**로 바꿨다. 측정 도구의 분해능을 먼저 본다는 §4-1-b 와 같은 이야기다.

**⚠⚠ 두 축을 한 변수로 뭉쳐서 재고 있었다** (2026-07-31)
측정 코드가 `sessions` 하나로 **무공 숙련과 유형 숙달을 동시에** 올렸다. 그래서 *"수련 200회"* 라는 기준이 실제로는 **정파 무공 10성 × 검 숙달 8성**이라는 뒤섞인 지점이었고, 그걸 "만렙" 이라 부르고 있었다.
→ 일반화: **측정에서 움직이는 변수는 하나여야 한다.** 그리고 그 변수의 이름이 실제로 무엇을 가리키는지 (경지인가 횟수인가, 무공인가 사람인가) 를 먼저 못박는다. 이름이 흐리면 기준도 흐려진다.

**⚠ 측정 오차보다 작은 조정은 조정이 아니다** (2026-07-31)
100전 표본의 표준편차가 4.9%p 인데 목표 구간이 12%p 폭이었다. 상수를 고쳐도 값이 안 움직이는 것처럼 보여 두 번 헛돌았다. → **§4-1-a 로 민감도 표본을 400전으로 올렸다.** 밸런싱 전에 측정 도구의 분해능부터 본다.

**⚠⚠ 판정 기준으로 삼은 지표를 실제로 재고 있는지 먼저 확인한다** (2026-08-01)
설계안 §5-3 과 `QiCostPerMorpheme` 주석이 **평타 전락률(10~30%)** 을 기력 설계의 판정 기준이라고 못박아 뒀는데, **그 값을 재는 코드가 없었다.** 그래서 기력 상수를 4 ↔ 3 으로 놓고 두 번 논쟁하는 동안 근거가 전부 산술 추정이었고, 실제로 재 보니 **0.0%** 였다 — 논쟁의 전제 자체가 틀려 있었다.
→ 일반화: **"이 값으로 판정한다" 고 적힌 지표는 그 문장을 쓸 때 같이 만든다.** 문서에만 있는 판정 기준은 판정 기준이 아니라 희망이다. §4-1-b 의 *"원인이 값이 아니라 표현력일 수 있다"* 와 한 계열인데, 이번엔 표현력이 아니라 **관측 자체가 없었다.**

**⚠⚠ 포화한 축은 압력이 사라지면 크기로 갚을 수 없다** (2026-08-01)
권(拳)의 유형 특성은 기력 소모 **−100%** 라 **이미 물리적 상한**이다. 기력 압력이 0 이 되자(전락률 0.0%) 이 특성은 *"0 을 100% 깎는 것"* 이 되어 통째로 사라졌고, 권은 유형 최하위(38.4%)로 떨어졌다. **크기를 올려 보정할 방법이 없다** — 100% 위가 없기 때문이다. 방어관통 160% 를 제시했다가 잡힌 것(§6-1)과 같은 벽이다.
→ 일반화: **상한에 닿은 축을 가진 대상은 그 축의 *압력*이 유지되는지로 지켜야 한다.** 압력을 줄이는 변경은 그 대상에게 되돌릴 수 없는 손실이다.

**⚠⚠ 상수를 바꾸면 그 상수가 등장하는 모든 표를 다시 뽑는다** (2026-08-01)
기력 상수를 4→3 으로 내려 계층 역전을 고친 날, **유형표를 다시 재지 않았다.** 그래서 *"유형 격차 7.4%p ✅"* 라는 판정이 인계 문서에 그대로 남아 반나절 넘게 사실로 통용됐다. 실제로는 그 변경이 권을 죽여 21.8%p 가 돼 있었다.
→ §5 의 *"같은 결과를 내는 손잡이가 여럿일 때, 다른 축이 무엇에 기대고 있는지로 고른다"* 는 **고른 뒤 재측정까지 해야 완결된다.** 고르기 전 검토만으로는 놓친다 — 실제로 `verify` 가 그때 회복·최대기력 인상은 막았지만 **소모 상수 인하도 같은 결과를 낸다는 것**은 보지 못했다.

**곱셈 누적은 후반을 독식한다** — 유형 숙달을 위력에서 뺀 이유(§3-4). 새 배율을 곱셈으로 넣지 않는다.
치명배율도 같은 이유로 **형태소 상수로 묶어** 숙련·성향이 곱해지지 않게 했고, 회귀 테스트(`CritTests.치명배율은_수련으로_커지지_않는다`)로 고정했다.

## 6. ⚠ 반드시 지킬 것

### 6-1. 작업 방식

- **⚠⚠ 새 안은 `verify` 를 통과한 뒤에 제시한다** (절대규칙 — `../CLAUDE.md` §5-C). 새 메커닉·공식·수치 체계·규칙 변경안, 그리고 선택지를 만들어 묻는 질문의 **각 선택지**가 대상이다.
  계기: 방어관통 **160%** 를 제시했다가 사용자가 잡았다 — 승률 숫자는 목표 구간에 맞았지만 **방어를 100% 무시하면 더 무시할 것이 없다.** 이름이 성능을 거짓말한 것이고, **측정치가 맞으면 안이 맞다고 착각하는 것**이 이 실패의 형태다. 숫자가 목표에 들어온 순간 자기 검토가 멈추기 때문에 자력으로는 잘 안 잡힌다
- **말 듣자마자 코드부터 쓰지 않는다.** 설계안을 먼저 정리해 검토받고 승인 뒤 구현한다
- **뼈대는 프로토타입 범위보다 깊고 넓게** 잡는다
- **⚠⚠ 콘텐츠는 계층 한 묶음씩 초안을 올려 승인받고 진행한다.** 138개를 한 번에 쏟지 않는다
- **⚠⚠ 사용자와 합의해 바꾼 규칙은 그 자리에서 `martial-resource-spec.md` 에 역반영한다.** 정의서가 코드와 어긋나면 다음 세션이 틀린 것을 믿는다
- **측정 근거가 있으면 밸런스 상수를 조정하고 결과를 보고한다** — 매번 묻지 않는다 (사용자 상시 위임)
- **모든 답변은 존댓말**

### 6-2. 코드 규율 (`projects/Jianghu/CLAUDE.md`)

1. **`Core` 는 UnityEngine 을 참조하지 않는다** — asmdef `noEngineReferences` + netstandard2.1 csproj 로 이중 강제
2. **난수는 `IRandomSource` 주입만** — `System.Random` 은 런타임마다 시퀀스가 달라 dotnet/Unity 결과가 갈린다
3. **C# 9 / .NET Standard 2.1 상한** — record·최상위문 금지
4. 테스트 메서드명은 **한글**, 그 외 식별자는 영어

### 6-3. 리서치 규율

- 게임 디자인 리서치는 **`game-research`** 에 축별 분리 위임 → 결론을 **`verify`** 통과시킨 뒤 채택
- ⚠⚠ **verify 는 실제로 결함을 잡았다** — 존재하지 않는 인용, 논리 비약, 연도 오류, 출처 불일치
- ⚠⚠ **그러나 verify 도 놓친다.** 중(中) 배경어 건은 verify 를 통과한 설계안이 **구현 단계에서 불가 판명**됐고, 한 번은 verify 가 **낡은 문서 항목을 근거로 삼았다.** 실측이 최종 심판이다

## 7. 지뢰 목록

- **⚠⚠ 파서 키는 한글이다.** 새 글자 추가 전 한글 충돌 확인. 중/重·광/光·성/聖·공/功·산/散 선점 사례

- **⚠⚠ `git commit -m` 에 따옴표 든 한국어를 넣으면 PowerShell 이 인자를 쪼갠다** — `git commit -F <파일>` 로
- **⚠⚠ `dotnet test` 와 Unity Test Runner 는 같은 어셈블리에 대해 판정이 갈릴 수 있다** (2026-08-01 밟음)
  - `Assert.Inconclusive` 를 dotnet 은 **건너뜀**으로, **Unity 는 빨강(실패)** 으로 집계했다(실측 ✅161·❌2). 지금까지 두 러너의 수가 늘 일치해서 사실상 같은 것으로 취급해 왔는데 **그 전제가 깨졌다**
  - → **`Assert.Ignore` 를 조건부로 호출한다.** NUnit3 결과 모델에서 `Ignored` 는 `Skipped` 카테고리이고 `Skipped` 는 `Failed` 와 별개 최상위 값이라 두 러너 모두 실패로 세지 않는다.
    ✅ **2026-08-01 Unity 실측으로 확인** — `✅161 · ❌0 · ○2 · 전체 163` 으로 dotnet 과 **완전히 일치**했다. 회색 2건은 Test Runner 트리에서 어느 테스트인지 그대로 보인다
  - ⚠ **정적 `[Ignore]` 어트리뷰트를 쓰지 말 것** — 조건이 해소돼도 영영 안 돈다. `[Explicit]` 은 아예 실행 대상에서 빠져 더 나쁘다
  - ⚠ Unity Test Runner **창의 색상 범례를 설명하는 공식 문서는 없다**(`docs-lookup` 조사). 판정 표시가 걸린 변경은 **에디터에서 실측**해야 한다
- **⚠ Unity 는 창에 포커스가 가야 파일 변경을 감지한다.** 백그라운드면 재컴파일이 안 된다
- **⚠ Test Runner 결과 목록을 펼치면 `HideFlags` assertion 이 Console 에 뜬다** (2026-08-01 관측) — 스택이 `UnityEngine.GUIUtility:ProcessEvent` 뿐인 **에디터 자체 잡음**이고 테스트는 159/159 초록이었다. 우리 버그로 착각하지 말 것. 상세는 §1-A
- **⚠ 이 프로젝트는 URP 다** (Built-in 아님). 인터넷 강좌 상당수가 구형 Built-in 기준
- **⚠ 에디터 버전을 올리지 말 것.** `6000.0.58f1 LTS` 고정
- **⚠ `Library\` `Temp\` `Logs\` 직접 열람 금지** — 훅이 차단한다. 로그 진단은 `diagnosis` 위임
- **⚠⚠ C 드라이브 여유 4.9GB** (2026-07-30). 프로젝트를 C 에 만들지 말 것
- **⚠ XML 주석 안에 `--` 를 쓸 수 없다** (csproj 주석에 `--project` 를 적었다가 빌드 실패)

- **⚠ 테스트에 절대 수치를 박지 말 것** — 밸런싱마다 깨진다. 값이 아니라 **모양**(순서·구조)을 검증한다
- **⚠ 테스트가 깨졌을 때 테스트부터 의심하지 말 것.** 이번에 깨진 것 중 하나는 **테스트 전제가 틀렸고**(복호권법의 호護는 등록돼 있었다), 하나는 **설계 지식을 알려줬다**(§5 사파 편차)
  - ⚠⚠ **2026-07-31 같은 테스트가 또 설계를 지켰다.** 기본 막기확률 5% 를 넣자 `사파는_전투_결과가_가장_일정하다` 가 깨졌다 — 막기는 성향과 무관하게 피해를 절반으로 만들어 사파의 ±5% 편차를 덮는다. **기본 막기를 0 으로 되돌렸다.** 성향 정체성은 이 프로토타입의 검증 대상 그 자체라 다른 축을 위해 내줄 수 없다
